## Naming Convention

**Format:** `YYYY-MM-DD_brief-topic-slug.md`

- `2025-11-14_field-journal-restoration.md`
- `2025-11-16_repository-consolidation.md`

## Guidelines

**What to document:**
- Significant debugging sessions
- Architecture decisions
- Feature implementation notes
- Experimental explorations
- Integration work
- Repository reorganization

**What NOT to document here:**
- Routine bug fixes (use git commit messages)
- Minor updates (use git commit messages)
- Personal notes (use private notes system)

**Session Status Definitions:**
- **Active**: Ongoing work, session in progress
- **Paused**: Work stopped temporarily, will resume later
- **Completed**: Work finished, all tasks resolved
- **Archived**: Historical record, no longer active

## Contributing

When adding a new dev session:
1. Create file using naming convention
2. Use the template above
3. Update the Session Index in this README
4. Commit with message: `docs: add dev session YYYY-MM-DD [brief topic]`
